# 文旅全场景智能辅助 Skill 系统 · 架构设计

## 一、设计理念

采用「**轻量化智能 Skill 协同**」架构：每个业务能力封装为独立、自包含的 Skill，通过编排入口（Orchestrator）动态协同，而非构建一个臃肿的单体应用。这一设计带来三个优势：

1. **渐进式披露**：每个 Skill 的元信息（name + description）常驻上下文，SKILL.md 主体在触发时加载，references 按需读取，控制上下文成本。
2. **可插拔扩展**：新增业务线只需新增一个 Skill，无需改动现有 Skill。
3. **面向实训**：清晰的能力边界与路由规则，便于教学演示与分模块实训。

## 二、总体架构

```
用户请求
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│  编排入口 Skill（wlt-tourism-assistant）                  │
│  · 角色扮演：统一的文旅智能助手身份                         │
│  · 意图识别：关键词 + 语义双重匹配                          │
│  · 任务路由：分派到对应业务 Skill                          │
│  · 协同编排：复杂需求编排多个 Skill 顺序执行                │
│  · 结果整合：统一语气与格式输出                             │
└──┬─────┬─────┬─────┬─────┬─────┬─────┬─────┬────────────┘
   │     │     │     │     │     │     │     │
 ①咨询 ②规划 ③营销 ④文创 ⑤匹配 ⑥数据 ⑦质检 ⑧舆情
   └─────┴─────┴─────┴─────┴─────┴─────┴─────┘
              共享知识库（领域知识·话术·模板·画像·指标）
```

## 三、八条业务线 · 两大板块

系统将八条业务线分为**游客与产品侧**（①–⑤）与**经营与保障侧**（⑥–⑧），前者直接服务游客体验与产品创新，后者支撑经营决策与服务/品牌保障。

| 板块 | 业务线 | Skill | 核心能力 |
|------|--------|-------|----------|
| 游客产品侧 | ① 咨询应答 | `wlt-consult-answer` | 三大业态问答、导览、预订指引 |
| 游客产品侧 | ② 方案规划 | `wlt-trip-planning` | 游玩·旅居·餐饮一体化规划 |
| 游客产品侧 | ③ 营销内容 | `wlt-marketing-content` | 文案、短视频、活动策划 |
| 游客产品侧 | ④ 文创创新 | `wlt-cultural-creative` | 文创与服务产品创新 |
| 游客产品侧 | ⑤ 客源匹配 | `wlt-customer-matching` | 客群画像与产品匹配 |
| 经营保障侧 | ⑥ 数据分析 | `wlt-data-analysis` | 客流/营收/转化/复购洞察 |
| 经营保障侧 | ⑦ 客服质检 | `wlt-service-quality` | 客服话术质检与服务评分 |
| 经营保障侧 | ⑧ 舆情口碑 | `wlt-reputation` | 舆情监测与危机应对 |

### 三大业态 × 业务线覆盖矩阵

三大业态（景区/酒店/餐饮）作为纵向领域维度贯穿业务线，其中①–⑤按业态细分能力，⑥–⑧横向贯穿三业态：

| 业务线 \ 业态 | 景区服务 | 酒店旅居 | 餐饮消费 |
|---------------|----------|----------|----------|
| ① 咨询应答 | 开放/门票/导览/交通 | 房型/入住/设施/政策 | 菜品/预订/口味/时段 |
| ② 方案规划 | 游览动线、主题游 | 住宿安排、房型搭配 | 美食路线、餐食安排 |
| ③ 营销内容 | 景区宣传/活动 | 酒店推广/套餐 | 餐饮种草/促销 |
| ④ 文创创新 | 文创商品/演艺体验 | 主题房/服务创新 | 联名食品/用餐体验 |
| ⑤ 客源匹配 | 适游度匹配 | 房型匹配 | 口味/场景匹配 |
| ⑥ 数据分析 | 客流/门票收入 | 入住率/RevPAR | 翻台率/客单价 |
| ⑦ 客服质检 | 景区客服话术 | 酒店客服话术 | 餐饮客服话术 |
| ⑧ 舆情口碑 | 景区差评/口碑 | 酒店评价 | 餐饮点评 |

## 四、Skill 设计明细

### 4.1 编排入口 `wlt-tourism-assistant`

- **职责**：角色扮演、意图识别、任务路由、协同编排、结果整合。
- **路由优先级**：咨询 → 规划 → 营销 → 文创 → 匹配 → 数据 → 质检 → 舆情（关键词 + 语义判定，详见 `references/意图路由规则.md`）。
- **协同原则**：先识别（意图/画像）→ 再规划/生成 → 最后整合输出。

### 4.2 游客与产品侧（①–⑤）

| Skill | 方法 | 特色 |
|-------|------|------|
| 咨询应答 | 判断业态 → 查知识库 → 组织应答 | 「先答后引」，自然植入二次消费 |
| 方案规划 | 五步法（需求→约束→匹配→生成→优化） | 时间轴组织 + 五大客群个性化适配 |
| 营销内容 | 四步法（人群→FAB卖点→平台调性→爆款结构） | 平台差异化，直接给成品 |
| 文创创新 | 五步法（文化提炼→洞察→发散→筛选→成型） | 「文化符号×载体×功能」创意矩阵 |
| 客源匹配 | 四步法（画像→标签化→规则匹配→推荐） | 四维标签 + 重合计分，推荐带理由 |

### 4.3 经营与保障侧（⑥–⑧）

| Skill | 方法 | 特色 |
|-------|------|------|
| 数据分析 | 四步法（指标→诊断→洞察→建议） | 结论可量化、建议带预期KPI、看板设计 |
| 客服质检 | 五步法（维度→评分→定位→建议→报告） | 五维质检 + 红线一票否决 |
| 舆情口碑 | 四步法（采集→情感分析→诊断→应对） | 危机三级分级响应、口径统一 |

## 五、数据流与协同示例

**示例：暑期经营复盘（多Skill协同）**

```
用户：「暑期营收下滑了，帮我分析一下并优化」
   │
   ▼ 意图识别（数据分析为主，含质检、营销）
   ├─ ① wlt-data-analysis     → 诊断营收下滑：客流+8%但客单价-15%
   ├─ ② wlt-service-quality   → 质检发现客服错失二次消费引导
   └─ ③ wlt-marketing-content → 产出「保客单价」组合套票营销文案
   │
   ▼ 结果整合
   经营诊断报告 + 话术改进 + 营销方案 + 预期KPI
```

## 六、关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| Skill 粒度 | 按业务线拆分（非按业态） | 业务能力稳定，业态是领域维度，避免组合爆炸 |
| 板块划分 | 游客产品侧 / 经营保障侧 | 区分「服务游客」与「支撑经营」两类能力 |
| 共享知识 | 编排入口持领域总览，业务 Skill 持细分知识 | 各 Skill 自包含，可独立运行 |
| 路由方式 | 关键词 + 语义双重匹配 | 规则透明可教，便于实训理解 |
| 输出规范 | 统一语气 + 结构化 + 数据时效标注 | 保证多 Skill 协同产出风格一致 |
| 可视化 | 各业务线专属渲染形态 | 强化区分度（时间轴/图表/评分条/环形图等） |
