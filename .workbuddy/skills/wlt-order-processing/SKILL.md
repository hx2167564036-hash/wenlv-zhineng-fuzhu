# 订单自动处理 Skill

## 角色定位

订单流程引擎：让每笔订单「秒级响应、规则清晰、异常有兜底」——从下单确认到退改售后全链路自动化。

## 触发场景

- 「订单确认太慢怎么自动化」「退票规则怎么设计」
- 「退款流程怎么走」「超售了怎么处理」

## 订单全链路状态机

```
待支付 → 已支付/待确认 → 已确认/待出行 → 已完成
   ↓         ↓               ↓
 超时取消   退款申请 → 审核中 → 已退款
             ↓
          改签/改期 → 新订单
```

每个状态定义：触发条件、自动动作、超时规则、通知模板（经 `wlt-push-message` 发送）。

## 核心规则引擎

### 1. 自动确认
- 库存充足 → 支付成功即确认（<5s）；
- 需人工确认的资源（包间/团队）→ 30分钟内确认，超时自动赔付规则。

### 2. 退改规则（阶梯示例）
| 距使用时间 | 门票 | 酒店 |
|-----------|------|------|
| >48h | 免费退 | 免费退 |
| 24-48h | 退80% | 退50% |
| <24h | 退50% | 不可退/免费改期1次 |
| 当天未使用 | 过期作废/转赠 | 按夜扣费 |

### 3. 异常处置
- **超售**：立即冻结售卖 → 按预订顺序保留 → 溢出客升级补偿（升舱/升房+歉意券）；
- **支付异常**：15分钟倒计时提醒 → 超时释放库存并通知；
- **不可抗力**（闭园/台风）：自动全额退 + 优先改期通道。

## 输出格式

- **流程图**：状态机 + 各节点自动动作与超时规则；
- **规则配置表**：退改阶梯、免审额度、自动退款上限；
- **异常处置预案**：按异常类型的 SOP（话术+补偿标准+升级路径）；
- **对账要点**：订单/支付/库存三方对账口径。

## 红线

- 退款**原路退回**并给明确到账时效（1-3个工作日），不拖延；
- 自动退款设金额上限，超限人工复核（防资损）；
- 退改规则**下单前明示**（勾选确认），事后不擅自变更；
- 不可抗力全额退不含糊，这是口碑底线也是监管要求。

## 与其他Skill协同

- 库存联动 → `wlt-crowd-analysis`（预约量）；规则咨询应答 → `wlt-consult-answer`；
- 异常工单 → `wlt-ticket-dispatch`；状态通知 → `wlt-push-message`。
