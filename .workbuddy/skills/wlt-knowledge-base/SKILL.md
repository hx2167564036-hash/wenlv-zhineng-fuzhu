# 文旅知识库 Skill

## 角色定位

知识工程师：把景区/酒店/餐饮的碎片化信息（门票、时间、房型、菜单、政策、故事）整理成**机器可检索、人可维护**的标准化知识库。

## 触发场景

- 「帮我们建一个知识库」「问答机器人的知识从哪来」
- 「这些POI信息怎么结构化」「知识库怎么保持更新」
- 「这条答案不准确，怎么修正」

## 知识条目标准结构

每条知识 = 6 个必填字段 + 4 个选填字段：

| 字段 | 必填 | 示例 |
|------|------|------|
| 条目ID | ✓ | KB-POI-0001 |
| 类别 | ✓ | 门票/开放时间/房型/菜品/政策/交通 |
| 标准问题 | ✓ | 景区几点开门？ |
| 标准答案 | ✓ | 旺季8:30-17:30（17:00停止入园） |
| 生效时间 | ✓ | 2026-06-01 至 2026-08-31 |
| 来源与责任人 | ✓ | 票务部·张经理·2026-05-20确认 |
| 变体问法 | ○ | 几点开门/营业时间/什么时候开门 |
| 关联条目 | ○ | 门票价格、预约政策 |
| 客群适配 | ○ | 亲子版/银发版话术 |
| 多媒体 | ○ | 图片/视频链接 |

## 构建四步法

1. **盘点**：按业态（景区/酒店/餐饮）× 类别列出知识清单，标注「有/缺/过期」；
2. **结构化**：逐条填入标准结构，补变体问法（每问3-5种说法）；
3. **挂接**：建立关联（门票↔预约↔退改），形成知识图谱；
4. **运营**：设「临期预警」（生效时间到期前7天提醒责任人复核）。

## 质检规则

- **时效性**：过期条目自动降权并标黄；
- **一致性**：同一事实多入口（官网/小程序/客服）答案必须一致；
- **可答性**：答案必须「一句话能说清」，长答案拆分子条目。

## 输出格式

- **知识条目表**：上述结构的批量条目；
- **缺口清单**：高频被问但库中缺失的问题（来自客服日志）；
- **维护看板**：条目总量、临期数量、命中率（被检索次数）。

## 红线

- 无来源/无责任人的条目**不得上线**；
- 价格、政策类条目必须有生效时间，永久有效的表述（「一直如此」）视为风险；
- 知识库与 `wlt-consult-answer` 的应答定期对账，不一致处限期修正。

## 与其他Skill协同

- 供检索 → `wlt-consult-answer`（咨询应答）、`wlt-multilingual`（多语翻译基底）；
- 缺口发现 → `wlt-service-quality`（客服质检日志反哺）。
