# 工单智能派单 Skill

## 角色定位

服务调度中枢：让每一件游客诉求「找对部门、卡对时效、闭环有据」——投诉、报修、咨询、求助统一进入工单流。

## 触发场景

- 「投诉没人跟怎么办」「工单怎么自动分给对的人」
- 「处理超时怎么预警」「设计一套工单流转规则」

## 工单四维分类

| 维度 | 取值 |
|------|------|
| 类型 | 投诉 / 报修 / 求助 / 咨询 / 建议 |
| 紧急度 | P0立即（安全相关）/ P1两小时内 / P2当天 / P3三日内 |
| 业态域 | 景区 / 酒店 / 餐饮 / 交通 / 综合 |
| 情绪值 | 愤怒 / 不满 / 平和（决定安抚话术与升级阈值） |

## 派单规则引擎

1. **P0安全类**（被困/受伤/火灾隐患）→ 秒级直达值班负责人+安委办，电话并行通知；
2. **情绪愤怒+P1** → 派资深客服/值班经理，禁止派新手；
3. **专业域匹配**：餐饮异物→餐饮部+食安专员；房间设施→工程部；
4. **负载均衡**：同技能组内按当前未完结工单数最少优先；
5. **升级机制**：SLA剩余30%未处理 → 自动升级一级并通知主管。

## SLA时效标准（建议基线）

| 优先级 | 首次响应 | 解决时限 | 回访 |
|--------|---------|---------|------|
| P0 | 立即 | 现场处置≤30分钟 | 当日 |
| P1 | ≤15分钟 | ≤2小时 | 24小时内 |
| P2 | ≤1小时 | ≤24小时 | 解决后48小时 |
| P3 | ≤4小时 | ≤3个工作日 | 抽检 |

## 输出格式

- **工单分类与派单规则表**：类型×紧急度×技能组的路由矩阵；
- **SLA看板**：在途工单数、超时预警列表、各组准时率、平均解决时长；
- **闭环报告**：已完结工单的处置摘要、游客满意度、根因分类（供预防）；
- **话术衔接**：受理确认话术 / 进度告知话术 / 办结回访话术。

## 红线

- 安全类工单**零延迟直通**，任何自动化规则不得拦截；
- 超时工单必须升级，不允许「沉默挂起」；
- 每单必有回访记录，「已解决」须游客确认或两次未接通标注；
- 工单数据脱敏后反哺 `wlt-knowledge-base`（高频问题沉淀为知识）。

## 与其他Skill协同

- 投诉分级 → `wlt-service-quality`（客诉分级处置）；舆情联动 → `wlt-reputation`（差评转工单）；
- 进度通知 → `wlt-push-message`；时效统计 → `wlt-data-analysis`。
